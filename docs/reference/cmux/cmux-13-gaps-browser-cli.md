Audited prefixes: `browser`, `cli` (~1069 strings), `socket`, `socketControl`, `command`, `commandPalette`, `applescript`, `remoteTmux`, plus the `Flags:` continuation lines inside `cli.help.*`. 1830 strings checked (key + English text) against every `catalog/cmux-*.md` file. ## CLI

### `cmux vm env` — per-machine environment variables (entirely uncovered)

Not mentioned anywhere in `cmux-05-cli-api.md`'s VM section. Source: `CLI/CMUXCLI+VMLayoutEnv.swift`.

- `cmux vm env set <machine> KEY=VALUE [KEY2=VALUE2 …] [--from-file <.env>] [-]` — sets env vars for every terminal/agent/command the machine starts; persisted at `~/.config/cmux/env` on the machine's durable volume, mode 0600, sourced by login/interactive shells. `--from-file`/`-` (stdin) read dotenv-style `KEY=VALUE` lines (blank lines and `#` comments skipped, optional `export `, matching quotes stripped) — preferred over inline `KEY=VALUE` so secrets don't land in shell history/`ps`.
- `cmux vm env ls <machine> [--show]` — lists variable names only; `--show` also prints values.
- `cmux vm env rm <machine> KEY [KEY2 …]` — removes variables.
- Delivery path: over the machine's end-to-end cmux-tui link into `cmux env receive` inside the machine (echo turned off before reading) — never through `vm.exec`, a command line, or a terminal screen; only names are ever printed back unless `--show`. Forks/snapshots/templates inherit the file (`cmux vm env rm` before promoting one).
- Keys must match `[A-Za-z_][A-Za-z0-9_]*`.
- Errors (verbatim): `vm env: unknown verb '%1$@'`; `vm env ls: unknown flag '%1$@'`; `vm env set: unknown flag '%1$@'`; `vm env set: give KEY=VALUE pairs, --from-file <.env>, or - for stdin`; `vm env set: cannot read %1$@`; `vm env rm: give at least one KEY`; `vm env rm: unknown flag '%1$@'`; `vm env rm: invalid variable name '%1$@' (keys match [A-Za-z_][A-Za-z0-9_]*)`; socket-level `vm.env_set requires \`id\`. Run \`cmux vm ls\` to find one.` / `vm.env_set requires \`entries\`: a non-empty array of {key, value}.` / `vm.env_set: every entry needs a string \`key\` and a string \`value\`.` / `vm.env_set: invalid variable name '%1$@' (keys match [A-Za-z_][A-Za-z0-9_]*).`
- Output: `OK set %1$ld variable on %2$@: %3$@` (singular) / plural form; `OK removed %1$ld variable on %2$@: %3$@` (singular) / plural form.

### `cmux vm layout` and the layout document schema (entirely uncovered)

Source: `CLI/CMUXCLI+VMLayoutEnv.swift`. Not the same as the Mac-side `cmux layout save/open` mentioned in cmux-05 — this is the cloud-machine variant, run over the shared `cmux layout …` guest CLI so the Mac CLI, an in-machine agent, and a linked peer share one "apply this layout" implementation.

- `cmux vm layout export <machine> [<workspace-id|name>] [--raw]` — prints a machine workspace's layout as the declarative layout document (same JSON `cmux new-workspace --layout`, `cmux layout save/open`, and `cmux.json` use). Default: the machine's focused workspace. `--raw` prints the daemon's own `LayoutDocument` (exact pane/tab ids) instead.
- `cmux vm layout apply <machine> (<file>|- | --from-saved <name>) [--workspace <workspace-id>|--name <name>] [--cwd <dir>] [--open]` — builds panes/splits/tabs on the machine from a layout document (file, stdin, or a Mac-saved layout from `cmux layout list`). Default creates a NEW workspace named after the document (`--name` overrides); `--workspace` targets an existing EMPTY workspace. Terminal `command`s are typed into login shells started in each surface's `cwd` (relative to `--cwd`, default the work user's home). `--open` then opens the workspace locally with the same geometry.
- Document schema (one of): `{"pane": {"surfaces": [{"type": "terminal", "name": "tests", "command": "bun test", "cwd": "work/app"}]}}`; `{"direction": "horizontal"|"vertical", "split": 0.6, "children": [<node>, <node>]}`; wrapped in `{"name": …, "cwd": …, "layout": <node>}` or `{"name": …, "workspace": {"cwd": …, "layout": <node>}}`. `horizontal` = side by side (first child left), `vertical` = stacked (first child top); `split` is the first child's share, 0.1–0.9, default 0.5. Surface `type`: `terminal` (name/command/cwd/env), `browser` (url/name); `project` surfaces are Mac-only and skipped on a machine.
- Mac validates the document before touching the machine, and names the offending JSON path; exit code 2 = invalid document.
- Layout node validation errors (verbatim, `cli.vm.layoutEnv.*`): `layout document must be a JSON object`; `'layout' must be a layout node object`; `layout node must be an object`; `layout node needs 'pane' (a leaf) or 'direction' (a split)`; `layout node must not have both 'pane' and 'direction'`; `'direction' must be "horizontal" or "vertical"`; `'split' must be a number (the first child's share, 0.1–0.9)`; `'children' must be an array of exactly 2 layout nodes`; `split needs exactly 2 children (got %1$@)`; `'pane' must be an object`; `'surfaces' must be a non-empty array`; `surface must be an object`; `'type' must be "terminal", "browser", or "project"`; `'%1$@' must be a string`; `value of %1$@ must be a single line`; `'env' must be an object of string values`; `browser surface needs url`; `'focus' must be true or false`; `not valid JSON`; `stdin is not UTF-8 text`; env-line parsing: `expected KEY=VALUE, got '%1$@'` / `line %1$@: expected KEY=VALUE, got '%2$@'`, `invalid variable name '%1$@' (keys match [A-Za-z_][A-Za-z0-9_]*)` / per-line variant; `no layout found: expected a node ({"pane": …} or {"direction": …}), {"layout": <node>}, or {"workspace": {"layout": <node>}}`; `this machine's cmux shim predates %1$@ support — reconnect it (cmux vm tree %2$@ --refresh) to heal, then retry`.
- Apply-specific errors: `vm layout apply: unknown flag '%1$@'`; `vm layout apply: cannot read %1$@`; `vm layout apply: empty layout document on stdin`; `vm layout apply: give a layout file, \`-\` for stdin, or --from-saved <name>`; `vm layout apply: --from-saved needs a layout name (see \`cmux layout list\`)`; `vm layout apply: pass a file (or -) OR --from-saved <name>, not both`; `vm layout apply: saved layout %1$@ could not be encoded`; `vm layout apply: the layout is applied to workspace %1$@ on %2$@, but it could not be opened here yet (%3$@). Open it with: cmux vm workspace open %4$@ %5$@`; `vm layout apply: the layout was applied but the machine reported no workspace id to open (output: %1$@)`.
- Export/misc: `vm layout export: unknown flag '%1$@'`; `vm layout: unknown verb '%1$@'`; layout document error wrapper `%1$@ at %2$@`.
- Timeouts: export 60s, apply 120s (`vm.exec` control-plane cap is 5 minutes per call).

### `cmux restore` / `cmux fork` — full error catalog (largely uncovered)

cmux-05 likely names these commands but not their error vocabulary. Source: `CLI/CMUXCLI+RestoreAdmission.swift`, `CLI/CMUXCLI+ForkExecution.swift`. - Stale/mismatched record: `this command no longer matches the session. Run 'cmux restore --surface' to use the current record.` (and fork's equivalent pointing at `cmux fork --surface`), for both checkpoint mismatch and kind mismatch.
- Corrupt/incompatible data: `this session's saved restore data is not compatible. Start the agent again in this terminal.` (incomplete data, malformed arguments, malformed record, unsupported mode — same text for all four causes).
- Environment: `the saved working directory is inaccessible. Restore access to it, then retry.`; `the saved agent command is unavailable. Make sure the agent is installed, then retry.`; `the saved process could not be started. Retry the visible restore/fork command.` (execve failure and shell-compatibility failure share this text).
- Provider setup sub-errors (restore only lists 7 variants, fork collapses to 1 `providerSetupFailed`): configuration failed, exited, signaled, start failed, timed out, unavailable, wait failed — each says "provider setup … Check the agent's provider settings, then retry." (or "took too long. Check the provider connection, then retry." for the timeout).
- Ownership/liveness (restore-only): `this session's live ownership could not be verified. Run 'cmux restore --surface' again.`; `another launch of this agent session is already starting. ## Corrections to other sections

- **cmux-08-mobile-dock-misc.md** lists `simulator` among the macOS-string prefixes it says were "catalogued above or listed here," but its only Simulator coverage is the phone-side streaming feature (`mobile.simulatorStream.*`). The `cli.simulator.*`/`cli.ios.*` CLI automation surface (driving a Simulator from the terminal — tap/swipe/gesture/camera/permissions/UI settings/Web Inspector/accessibility/screenshots) is a distinct, undocumented feature; see "CLI" above.
- **cmux-05-cli-api.md**'s "My Devices" section describes discovery/pairing but doesn't state that `vm open device:<uuid>@<tag>/...` is the actual addressing scheme used to open a terminal on another Mac — the two features are connected only through source code, not through the doc's cross-references.
- `cli.vm.tree.hiddenTabs`, `cli.localTmux.output.foundStale`/`removedStale` and `cli.workspaceGroup.response.closed.one`/`dissolved.one` are plural forms (one/other), e.g. hiddenTabs reads "(+%d hidden)". An earlier string dump read them as untranslated; they are not.
