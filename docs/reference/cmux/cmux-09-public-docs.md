## Advertised features (grouped)

### Core terminal (macOS app)
- **Native macOS terminal built on libghostty**: "A Ghostty-based macOS terminal with vertical tabs and notifications for AI coding agents" (README tagline); "native Swift + AppKit, no Electron" (home.json `feature.lightweight`). Source: `Sources/` is a Swift/AppKit app; `ghostty.h`, `ghostty` submodule present at repo root. Verified.
- **Vertical + horizontal tabs / workspaces / split panes**: sidebar shows git branch, PR status/number, working directory, ports, notification text (README). Split right (⌘D) / down (⌘⇧D). Source: `Sources/` has sidebar, pane, split files (e.g. `DockSplitStore.swift`, many `*Sidebar*.swift`). Verified.
- **Notification rings & panel**: panes get a blue ring, tabs light up, notification popover, macOS desktop notification; fires via OSC 9/99/777 or `cmux notify` (docs `notifications`, home.json). Source: `Sources/RemoteTmuxSessionMirror+OutputRouting.swift` and others reference OSC777; `Sources/AgentNotificationDelivery.swift`. Verified.
- **In-app/embedded browser**: split a real browser pane, scriptable API "ported from agent-browser" (README, vercel-labs/agent-browser credited). Design Mode (visual page editing, added 0.64.20). Source: `Sources/Panels/BrowserPanel.swift`, `Sources/BrowserAvailabilityManagedPolicy.swift`. Verified.
- **Browser import**: cookies/history/sessions from Chrome, Firefox, Arc, and "20+ browsers" (README bullet; docs `configuration.browserLinkBehavior` describes allow lists; blog `passkeyAuth` mentions `cmux browser import`). Source: not individually greped per-browser, but `cmux browser cookies import` CLI is in 0.64.4 changelog and confirmed CLI surface exists (`CLI/`). Verified (CLI exists); per-browser count of "20+" is a marketing claim, unverified in source enumeration.
- **Ghostty-config compatible**: reads `~/.config/ghostty/config` for theme/font/colors; cmux is explicitly "not a fork of Ghostty," uses libghostty as a library (README FAQ, home.json `faqGhosttyA`).
- **GPU-accelerated rendering** via libghostty (README, home.json `feature.gpuAccelerated`).
- **Auto-updates via Sparkle**; update pill in titlebar (`getting-started` docs, README).
- **Keyboard shortcuts, extensively customizable**: two-step chords supported via `cmux.json`, VS Code-style `when` clauses for per-action context (docs `keyboardShortcuts`, `configuration.shortcuts.when`). Verified in `docs_en.json` `configuration.schemaDescriptions.shortcuts.when`.
- **Open source, GPL-3.0-or-later** (relicensed from AGPL-3.0 at v0.63.2, per changelog and `LICENSE` file header: "GPL-3.0-or-later"). Note: home.json FAQ (`faqGhosttyA`... actually `feature.openSourceDesc`) says "free and GPL-licensed"; README footer says the same and offers commercial terms for GPL-incompatible orgs.

### Workspaces, panes, surfaces (concepts model)
- **Four-level hierarchy**: Window → Workspace (a.k.a. "tab" in UI) → Pane (split region) → Surface (tab within a pane, holding a Terminal or Browser panel) (docs `concepts`). CMUX_SURFACE_ID / CMUX_WORKSPACE_ID env vars documented. Source: concept matches CLI's `--workspace/--surface` flags in `CLI/cmux.swift`. Verified.
- **Workspace Groups**: collapsible named sidebar sections with an anchor workspace, pin/rename/color/icon, `cmux workspace-group` CLI (create/delete/set-color/set-icon/move/list), config under `workspaceGroups` key in `cmux.json` (docs `workspaceGroups`). Added 0.64.11 per changelog. Source: CLI subcommand file not found by exact name search but `CLI/cmux.swift` and `CLI/CMUXCLI+CommandSuggestions.swift` reference workspace-group; feature is real per changelog 0.64.11. Verified (changelog + docs align; CLI file present under a different filename, not isolated).
- **Saved workspace layouts**: capture current split arrangement as a named layout from the plus-button menu, set a default for new workspaces (docs `customCommands.workspaceActionsSaveDesc`; added 0.64.18).

### Custom Commands / cmux.json actions
- `actions` registry (nightly-only per docs callout) mapping IDs to: built-in aliasing, shell `command`, `agent` launch, `workspaceCommand`, or inline `workspace` definitions; fields include `title`, `subtitle`/`description`, `keywords`, `palette`, `shortcut`, `target`, `confirm`, `newWorkspaceMenu` (docs `customCommands`). Legacy `commands` array (simple shell commands, workspace layouts with layout trees of split/pane nodes) still supported. Project config at `.cmux/cmux.json` overrides global `~/.config/cmux/cmux.json`. Source: `Sources/DockConfigFile.swift`, `Sources/DockConfigurationLoadResult.swift`, `Sources/DockScope.swift` confirm a JSON-config-driven customization system exists. Verified structurally.

### Dock (right-sidebar controls)
- JSON config (`dock.json`) with a `controls` array; terminal or browser control types; fields `id`, `title`, `command`, `type`, `url`, `chrome`, `cwd`, `height`, `env`; project (`.cmux/dock.json`) vs. global (`~/.config/cmux/dock.json`) precedence (docs `dock`). Source: `Sources/DockConfigFile.swift`, `Sources/DockSplitStore.swift`, `Sources/DockScope.swift`, `Sources/DockConfigurationLoadResult.swift`. Verified.

### TextBox (Beta)
- Rich terminal input surface for composing prompts before sending; settings for show/focus on new terminals, max lines, configurable submit actions (docs `textBox`; added as beta feature per changelog 0.64.18 "configurable submit actions"). Verified via `configuration.schemaDescriptions.terminal.textBox*` keys present in `docs_en.json`.

### Session Restore
- Restores window/workspace/pane layout, working directories, terminal scrollback (best-effort), browser URL/history on relaunch; does **not** checkpoint arbitrary live process state (tmux/vim/shells reopen fresh) (docs `sessionRestore`, README). Agent resume via captured native session IDs: table of supported agents (Claude Code, Codex, Grok, OpenCode, Pi, Amp, Cursor CLI, Gemini, Rovo Dev, Copilot, CodeBuddy, Factory, Qoder per README; docs table also lists feed-bridge hook types per agent — PermissionRequest, PreToolUse/PostToolUse, beforeShellExecution, Hermes-specific events). `cmux hooks setup [agent]` installs hooks. Custom surface resume bindings via `cmux surface resume set/show/clear`, trust model with approved signed prefixes, secrets stripped before storage (docs, README). Snapshot stored at `~/Library/Application Support/cmux/session-<bundle-id>.json`; agent hook session maps at `~/.cmuxterm/<agent>-hook-sessions.json`. Source: session/resume machinery corroborated by many `Sources/Agent*Restore*.swift`, `Sources/Agent*Resume*.swift`, `Sources/SessionPersistence.swift` files. Verified.

Cloud is in beta and launches in the next major release"). Verified via changelog cross-reference; deeper source paths not individually enumerated (time-boxed).

### Managed Device Policies (MDM)
Configuration-profile (macOS Custom Settings payload) forced preferences targeting `com.cmuxterm.app`, tier-0 (win over env vars, user settings, `cmux.json` imports). Documented keys (Boolean unless noted):
- `DisableEmbeddedBrowser`, `DisableRemoteControl`, `DisableDeviceDiscovery` (implied by "device discovery" desc), `DisableIncomingDeviceAccess`, `DisableCloud`, `DisableRemoteConnections`, `DisableFileTransfer`, `DisableIrohNetworking`, `DisableTelemetry`, `DisableAutoUpdate`, `DisableWebhooks` (automation webhook action), `DisableTLSBypass` (certificate-error click-through), `DisableComputerUse`, `DisableCustomSidebars`, `DisableAICredentialUpload`. Browser allowlist: `BrowserURLAllowlist` (array of strings), `BrowserAllowLocalhost`, `BrowserAllowLocalFiles` (both default true). Policies apply at launch, on preference change, on activation, and via ~1-minute periodic re-check. Verified in source: `grep` confirms `DisableEmbeddedBrowser` in `Sources/AppDelegate+ManagedPolicy.swift`, `Sources/BrowserAvailabilityManagedPolicy.swift`, `Sources/Panels/BrowserPanel.swift`; `BrowserURLAllowlist` in `Sources/AppDelegate+ManagedPolicy.swift`, `Sources/ManagedPolicyEnforcementObserver.swift`, `Sources/CmuxSettingsJSONPathSupport.swift`; `DisableComputerUse` in `Sources/TerminalSurfaceRuntimeWiring.swift`, `Sources/AppDelegate.swift`. **Verified from primary source.**

### Remote tmux (Beta)
- Mirrors a remote tmux session over SSH control mode (`tmux -CC`) into native cmux workspaces/tabs/splits; `cmux ssh-tmux <destination>` (optional `--new-window`); requires tmux 3.2+ remote; socket methods `remote.tmux.sessions|attach|mirror|detach|state`; limitations include reconnect-with-backoff, single-line-only real bracketed paste, primary-screen reflow left to tmux (docs `remoteTmux`). Distinguished from `cmux mosh-tmux` (Mosh-backed roaming tmux terminal, not the native mirror). Source: `Sources/RemoteTmuxSessionMirror.swift`, `Sources/RemoteTmuxSessionMirror+OutputRouting.swift`, `Sources/RemoteTmuxControlConnection+Commands.swift`; CLI references in `CLI/CMUXCLI+SSHHelp.swift`. Verified.

### SSH
- `cmux ssh` reads `~/.ssh/config`; flags `--name`, `--command`, `-p/--port`, `-i/--identity`, `-o` (raw SSH options), `--transport ssh|mosh`, `--no-focus`. Browser panes route through remote network (no port-forwarding needed); drag-and-drop upload via scp; agent notifications relay home over the SSH-uploaded Go relay daemon `cmuxd-remote` (JSON-RPC over stdio, versioned/SHA-256-verified, stored at `~/.cmux/bin/cmuxd-remote/...`); reconnect with capped exponential backoff (docs `ssh`, README). Mosh transport (`--transport mosh`) requires local Mosh 1.4+ and remote `mosh-server`. SSH deep links (`cmux://ssh?...`, `cmux-nightly://`, `cmux-dev://`) with a fixed parameter set (host, user, port, title, connectTimeout, serverAliveInterval/CountMax, hostKeyPolicy, noFocus); external links cannot carry identity files/raw options/commands (security constraint). Verified structurally against changelog SSH entries across many releases (0.64.23–0.64.7 range) and `Sources/` files referencing SSH/relay.

### Notifications
- Lifecycle: received → unread (badge) → read (on view) → cleared. Suppression when window/workspace focused or panel open. Custom shell command hook (`Settings > App > Notification Command`) run via `/bin/sh -c`. OSC 777 (simple, RXVT) and OSC 99 (rich, Kitty, supports subtitle+ID) escape-sequence protocols; `cmux notify` CLI. Claude Code hooks integration; GitHub Copilot CLI hooks integration. tmux passthrough note. `notifications.hooks` in `cmux.json`: JSON-in/JSON-out hook chain, off by default, receives agent-event context (`agent.kind`, `category`, `pending`, `isSubagent`) as of the notifications doc and 0.64.23 changelog entry. `notifications.hooksMode: "replace"` to override inherited hooks. Verified: `Sources/AgentNotificationDelivery.swift`, `Sources/AgentNotificationGate.swift`, `Sources/AgentNotificationAdmissionWaiters.swift` exist; OSC777 referenced in `Sources/RemoteTmux*` files (remote-tmux forwards OSC777/9, per 0.64.23 changelog).

### CLI Reference / Socket API
- Unix socket (release path vs. debug/tagged-debug path documented), `CMUX_SOCKET_PATH` override, one JSON request per line, `method`+`params` only (legacy `command` payload unsupported). Access modes: `off`, `cmuxOnly` (default), `allowAll` (env-override only, `CMUX_SOCKET_MODE=allowAll`). CLI flags: `--socket`, `--json`, `--window`, `--workspace`, `--surface`, `--id-format`. Command groups documented: workspace (`list/new/select/current/close`), split (`new-split`, directions left/right/up/down, `--command`), surfaces (`list-surfaces`, `focus-surface`), input (`send`, `send-key`, per-surface variants), notifications (`notify`, `list-notifications`, `clear-notifications`), sidebar metadata (`set-status`, `clear-status`, `list-status`, `set-progress`, `clear-progress`, `log`, `clear-log`, `list-log`, `sidebar-state`), utility (`ping`, `capabilities`, `identify`). Env vars: `CMUX_SOCKET_PATH`, `CMUX_SOCKET_ENABLE`, `CMUX_SOCKET_MODE`, `CMUX_WORKSPACE_ID`, `CMUX_SURFACE_ID`, `TERM_PROGRAM=ghostty`, `TERM=xterm-ghostty`. Source: `CLI/cmux.swift` contains literal `case "ping":`, `case "capabilities":`, `case "identify":` matches at multiple line numbers (verified via grep, e.g. lines 5385, 5391, 6548, 18064, 18080, 18701). **Verified from primary source.**

### Browser Automation
- `cmux browser` command group: navigation/targeting, waiting (selectors/text/URL fragment/load-state/JS condition), DOM interaction (`--snapshot-after` on mutating actions), inspection (structured getters + screenshots/snapshots), JS eval/injection, frames/dialogs/downloads, state/session (cookies, local/session storage, full snapshots), tabs/logs (console/errors). Targeted by positional surface ref or `--surface`. Documented as the mechanism agents use to verify their own web changes (docs `browserAutomation`, home.json `faqBrowserA`). Not independently grepped beyond confirming `Sources/Panels/BrowserPanel.swift` and browser-availability files exist; command surface corroborated by the CLI Reference doc's socket-method framing and multiple browser-related changelog entries (e.g., 0.64.23 "an MDM-enforceable URL allowlist... `cmux browser <surface> download list`... `cmux browser zoom <factor>`").

### cmux Computer Use
- Bundled MCP server `cmux-cua` gives Claude Code and Codex sessions in cmux tools to control native macOS apps: screenshots + accessibility tree inspection, click/type/scroll/drag/keyboard. Codex tool: `get_app_state`. Claude Code tools: `list_apps`, `list_windows`, `get_window_state`, `perform_actions` (native profile). Setup: enable in Settings → Computer Use, grant Accessibility + Screen Recording to the helper. Disable via `CMUX_COMPUTER_USE_MCP_DISABLED=1` per-launch, or the Settings toggle / `DisableComputerUse` MDM policy. Distinct from browser automation (native windows vs. cmux browser panes) (docs `computerUse`). Source: `skills/cmux-cua/SKILL.md` exists; `DisableComputerUse` confirmed in `Sources/TerminalSurfaceRuntimeWiring.swift` and `Sources/AppDelegate.swift`. Verified.

### Task Manager

### Agent integrations (agent-integrations/*)
- **Claude Code Teams** (`cmux claude-teams`): tmux shim intercepts Claude Code's native tmux-based teammate mode and redirects panes into cmux splits; env vars `TMUX`, `TMUX_PANE`, `CMUX_SURFACE_ID`, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, `CMUX_SOCKET`; nightly-only per docs callout.
- **oh-my-opencode** (`cmux omo`): shadow OpenCode config (`~/.cmuxterm/omo-config/`), installs `oh-my-opencode` npm package, enables its tmux mode, intercepts via a `tmux` shim at `~/.cmuxterm/omo-bin/tmux`. Nightly-only.
- **oh-my-codex** (`cmux omx`): shim at `~/.cmuxterm/omx-bin/tmux`, requires OpenAI Codex CLI + auth (`omx doctor`).
- **oh-my-claudecode** (`cmux omc`): shim at `~/.cmuxterm/omc-bin/tmux`, requires Claude Code CLI installed/authenticated.
- **oh-my-pi** (`omp`): hooks extension written to `~/.omp/agent/extensions/cmux-omp-session.ts`, cmux upgrades in place; provides busy/idle status, turn-end notifications, session resume/fork, auto-naming, Task Manager attribution.
All five corroborated by matching CHANGELOG entries (0.64.23 "Claude Code Agent Teams teammate panes in SSH workspaces run on the remote PTY"; 0.63.2 "`cmux omx` and `cmux omc` agent integrations"; 0.63.0 "`cmux omo` command for oh-my-openagent integration"; 0.62.0 "cmux claude-teams launcher").

### cmux TUI (separate open-source product, Rust)
- Cross-platform (macOS/Linux/Windows) terminal workspace tool distinct from the macOS app: workspaces → screens → split panes → terminal/browser tabs; default prefix Ctrl-b (press twice for literal); headless sessions with named Unix sockets, attach/detach; remote machine rail (Unix-socket or SSH targets, strict host-key checking, no agent/port forwarding); browser tabs drive real Chrome/Chromium via CDP with persistent profiles; control socket + CLI automation with typed bindings for TypeScript, Python, Go, Java, Rust; config file overridable via `CMUX_TUI_CONFIG`. Install scripts verify SHA-256 checksums (docs `tui.docs`, `tui.marketing`). Source: repo has a `cmux-tui` directory at root (confirmed via `find`); not deep-inspected beyond directory presence (time-boxed) — **verified directory exists, feature claims not individually source-checked beyond that**.

## Documented config formats

### `~/.config/cmux/cmux.json` (also `.cmux/cmux.json` project-local)
Top-level sections documented in `docs/configuration` and `docs/customCommands` (schema descriptions in `docs_en.json` `configuration.schemaDescriptions`):
- `packs` — local cmux pack files/directories loaded before this config (path string or `{path}` object).
- `computerUse` — `{enabled, showInMenuBar}`.
- `agentChat` — `{url, startCommand, keys.ctrlJ, fonts: {sansFamily, bodyFamily, family, baseSize, bodySize, monoFamily, codeFamily, codeSize, monoSize, codeLineHeight}}`.
- `automation` — `{ampIntegration, suppressSubagentNotifications, workspaceAutoNaming, autoNamingAgent}`.
- `app` — `{confirmQuit, windowTitleTemplate, devWindowDisplay, warnBeforeQuit (legacy), warnBeforeClosingTabXButton, hideTabCloseButton, forkConversationDefaultDestination, globalFontMagnification, paneResizeStepPixels}`.
- `terminal` — `{adaptiveDefaultTheme, agentHibernation, agentHibernationEnabled, copyOnSelect, scrollSpeed, sessionContentMaxWidth, sessionContentAlignment, showTextBoxOnNewTerminals, focusTextBoxOnNewTerminals, textBoxDefaultSubmitAction, textBoxSubmitActions[] (each: id, title, kind, commandTemplate, preservePromptAfterLaunch, systemImage, assetName, imagePath, backgroundColorHex), autoResumeAgentSessions}` (last one from README).
- `browser` — `{defaultSearchEngine, customSearchEngineName, customSearchEngineURLTemplate, defaultZoomLevel, askWhereToSaveDownloads, urlAllowlist}`.
- `workspaceGroups` — `{newWorkspacePlacement: afterCurrent|top|end, byCwd: {<cwd>: {newWorkspacePlacement}}}`.
- `markdown` — `{fontSize, fontFamily, maxWidth}`.
- `canvas` — `{paneGap, snappingEnabled}`.
- `fileEditor` — `{wordWrap, syntaxHighlighting, lineNumbers, indentGuides, currentLineHighlight, tabWidth}`.
- `sidebar` — `{notificationMessageLineLimit, rightMaxWidth}`.
- `fileExplorer` — `{doubleClickAction: preview|defaultEditor|preferredEditor}`.
- `diffViewer` — `{defaultLayout}`.
- `shortcuts` — `{when: {<actionId>: <boolean expression>}, showModifierHoldHints}`; `when` clause vocabulary: boolean keys `sidebarFocus, browserFocus, markdownFocus, filePreviewTextEditorFocus, simulatorFocus, terminalFocus, commandPaletteVisible, terminalFindVisible, workspaceCanvasLayout`; typed keys `sidebarMode` (string: files/find/sessions/feed/dock), `paneCount`/`workspaceCount` (int); operators `!`, `&&`, `||`, `()`, `==`, `!=`, `=~` (regex), `<`, `<=`, `>`, `>=`, `in [a,b]`.
- `paneBorderColor`, `activePaneBorderColor` — pane divider colors.
- `notifications` — `{paneFlashColor, suppressOnlyFocusedSurface, agentPermissionPrompt, agentTurnComplete: whenIdle|always|never, agentIdleReminder, soundOverrides: {<agent>.<alertType>: soundOverride}, hooks[], hooksMode: replace}`.
- Actions registry (`actions`): `{title, subtitle/description, keywords[], palette (bool, default true), shortcut, target: currentTerminal|newTabInCurrentPane, confirm, newWorkspaceMenu}` plus a type-specific payload for built-in alias / `command` / `agent` / `workspaceCommand` / inline `workspace`.
- Legacy `commands[]`: `{name, description, keywords, command, confirm}` (simple) or workspace command `{name, cwd, color, env, setup, layout}` with a recursive layout tree of split nodes (`direction`, `position` 0.1–0.9, two children) and pane nodes (surfaces: `{name, command, cwd, env, url (browser), focus}`).
- `ui.newWorkspace.action`, `ui.newWorkspace.contextMenu` (alias `rightClick`) — menu entries as action IDs, action objects, or `{type: "separator"}`.
- `ui.surfaceTabBar.buttons` — icon objects: `{type: "symbol", name}`, `{type: "emoji", value, scale}`, `{type: "image", path}` (SVG/PDF/PNG/JPEG/GIF/TIFF/BMP/HEIC/HEIF/WebP/AVIF/ICO/ICNS supported).
- `workspaceGroups` (root, distinct from `workspaceGroups.byCwd`) config keyed by anchor cwd for per-group color/icon/placement/menu actions (docs `workspaceGroups.configNote`).

### `dock.json` (`.cmux/dock.json` project, `~/.config/cmux/dock.json` global)
`{"controls": [{id, title, command, type: terminal|browser (default terminal), url, chrome (bool, default true), cwd, height, env}]}`.

### Automations (`~/.cmuxterm/automations.json`)
Rule engine with notify/RPC/run/webhook actions, rate limits, dry-run matching (added 0.64.23; CLI `cmux automation list|show|test|enable|disable|logs|reload`). Not documented on a dedicated docs page as of this snapshot — **in source/changelog but not in the docs nav** (see closing section).

### MDM configuration profile
Custom Settings payload targeting `com.cmuxterm.app`; Boolean keys and one string-array key (`BrowserURLAllowlist`) as enumerated above under Managed Device Policies.

| Plan | Price | Headline |
|---|---|---|
