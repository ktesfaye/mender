# Mobile, dock, diff viewer and everything else

This covers the companion iOS app end to end, the Dock and Canvas macOS panel systems, the diff viewer/comments/file-explorer/markdown/search surfaces, the Debug menu and diagnostics, and the cmux.com web product outside the docs. All text below is verbatim from `cmux-strings.tsv` (macOS) or `ios/cmux/Resources/Localizable.xcstrings` (iOS) unless noted.

## The iOS app

The iOS client lives in `Packages/iOS/*` (UI/state), `Packages/Shared/*` (transport/sync shared with macOS), and `ios/cmuxPackage/Sources/cmuxFeature` (composition root only — `CMUXMobileRuntime`, `MobileAuthComposition`, `CMUXMobileRootScene`). It is a remote control + notification hub for cmux running on a paired Mac; it runs no agents itself.

### Sign-in

Entry screen (`SignInView.swift`, strings `mobile.signIn.*`, `auth.error.*`): title "cmux", subtitle "Sign in to connect to your Mac workspaces." Methods, top to bottom: **Sign in with Apple**, **Sign in with GitHub**, **Sign in with Google**, then a divider "or continue with email" and **Email me a code**. Email flow: enter address (validated, "Please enter a valid email address."), a 6-character code is emailed ("We sent a code to %@"), entered via placeholder `ABC123` ("Enter the 6-character code from your email." on error). A separate verification path exists for email-link sign-in: "We sent a verification link to %@. Open it, then return here." with **I verified my email**, a "not verified yet" retry message, and **Resend verification email**.
- Session restore: on relaunch, a "Restoring session" / "Checking your saved session. Sign-in options are paused until this finishes." state blocks the sign-in buttons; a stuck restore surfaces "Still restoring session" with retry.
- Auth errors are a full taxonomy (`auth.error.*`): apple_config, browser_sign_in_failed, code_expired, config, email_exists, email_requires_verification, invalid_callback, invalid_code(_short), invalid_email, invalid_mfa, network(_error), oauth_linked, passkey_failed, rate_limit, server_error, timed_out, unauthorized, user_not_found, wrong_password — each a distinct user-facing sentence (e.g. "Too many attempts. Please wait a moment and try again.").

### Onboarding (`OnboardingFlowView.swift` + `Onboarding*View.swift`)

A five-stage swipeable/paged tour shown once after first sign-in, `stage: OnboardingStage` = `.agents → .notifications → .push → .pairing → .connect`, each with progress text "Step %1$d of %2$d". Back/Skip always available except stepping back off the first page; Skip fires analytics `ios_onboarding_skipped` and a diagnostic event.

1. **Agents** — "Your agents keep working on your Mac" / "Track every workspace from your phone." Primary: Continue.
2. **Notifications** — "Every agent alert, in one place" / "Review every agent alert in one feed."
3. **Push** — "Know the moment an agent needs you" / "Get a push when an agent is waiting, and reply right from the Lock Screen." Primary **Enable Notifications** (calls the OS permission prompt — the one and only place push permission is first requested; a re-tap while the system alert is pending is ignored, guarded by `isPushEnableInFlight`), secondary **Not Now** (declines without touching the OS, disabled while the enable is in flight).
4. **Pairing** — "Pair your Mac" static explainer page.
5. **Connect** (`OnboardingConnectionView`) — live connection attempt with a method picker:
   - **Iroh** ("Same-account Macs connect automatically.") — default; states: idle "Ready to look for your Mac", searching "Looking for your Mac…", fallback "Couldn't connect to your Mac yet" with **Use QR Code Instead**, ready "Connected securely". Trust line: "End-to-end encrypted. Relays cannot read your terminal traffic."
   - **Tailscale Only** ("Scan once to authorize the Mac.") — shows **Scan Pairing Code**, body: "Install Tailscale on both devices and join the same network, then scan the pairing code once."
   - A **Keep Mac Awake** offer card can appear here (`OnboardingKeepAwakeCard`, "Prevent your Mac from sleeping while cmux is open."), togglable inline with async confirm/revert.
   - Finishing logic (`finishOrRetry`): idle/fallback → retry connection (or start Tailscale pairing if that method is selected); searching → no-op; ready → completes onboarding (`onComplete`, records `ios_onboarding_completed`). If the user reaches Connect before finishing auth, Continue instead calls `finishBeforeAuthentication()` (captures `ios_onboarding_tour_completed` and completes without a Mac yet).
   - Selecting Tailscale while an Iroh connection is already `.ready` immediately starts Tailscale pairing rather than silently completing onboarding on the old connection (explicit guard in code, `shouldStartTailscalePairing`).

Every stage transition and terminal action is instrumented: `ios_onboarding_scene_viewed`, `_push_enable_tapped`, `_push_declined`, `_connection_retried`, `_connection_method_selected`, `_pairing_started`, `_keep_awake_set`/`_reverted`, `_completed`, `_skipped`, `_tour_completed` — each carrying `context` and `stage`.

### Pairing (`PairingView.swift`, `MobilePairingModel/View(+Connected)`, strings `mobile.pairing.*`, `mobile.addDevice.*`)

Reached from onboarding, Settings → Devices, or the empty workspace list. Title "Pair with computer", subtitle "Scan the QR shown on your computer, or enter a pairing code." Camera-based QR scanner (**Scan QR Code**) with an **Enter Manually** fallback (`mobile.pairing.codePlaceholder` "Pairing code", plus a raw host/port form: HOST placeholder `100.x.x.x (Tailscale IP; 127.0.0.1 in Simulator)`, PORT placeholder `58465`, optional NAME `Work Mac`).
- Camera permission states: denied ("Camera Access Required" / "Allow camera access in Settings…"), restricted ("Camera access is restricted on this device. Use a pairing link or the manual form instead."), unavailable.
- A vast, very specific error/guidance matrix drives what's shown when a scan or connect fails — each pairs a `mobile.pairing.*Format` failure string with a `mobile.pairing.guidance.*` remediation string, e.g.:
  - Wrong QR: "This isn't a cmux pairing QR. On cmux 0.64.17, scan the Pair iPhone code. On newer versions, scan the code in Mobile Pairing."
  - QR points at localhost: "This code points at the Mac itself (localhost), so your iPhone can't use it…"
  - Email mismatch: "This QR is for %@, but this iPhone is signed in as %@. Sign in with the same email as the Mac, then scan again."
  - Different auth environments (dev vs prod builds) — three distinct sentences depending on which side is which build channel.
  - Version skew: `macVersionTooOld` has stable/nightly/unknown-version variants, each naming exact minimum versions; a "compatibility mismatch" dialog with **Continue anyway** lets the user override at their own risk ("Pairing across different compatibility levels can break terminal input, workspace sync, or notifications.").
  - Network-layer failures: DNS failed, connection timed out (with host:port interpolated), connection dropped, host unreachable, local network permission blocked ("iOS blocked the connection. Allow cmux to use the Local Network in iOS Settings…"), route cleanup stuck ("Force-quit and reopen cmux on this iPhone…").
  - `mobile.pairing.versionWarningTitle` "Compatibility mismatch" surfaces as a confirm sheet before connecting across mismatched builds.
- Successful pairing state (`MobilePairingView+Connected.swift`) shows a connected summary before handing off to the workspace list.

### Connections / Computers (`mobile.connections.*`, `mobile.computers.*`, `mobile.deviceTree.*`, `DeviceTreeView.swift`, `MacComputerRow/DetailView.swift`)

A **Computers** list (Settings → Devices, or a picker) of every paired Mac, each a row you tap to reconnect. Per-computer state: connection method badge (Iroh / Tailscale Only / Direct / Debug / WebSocket), presence, and a visibility switch ("Show this computer on this iPhone" — hiding is device-local only, the Mac stays signed in). Hidden computers move to a separate "Hidden Computers" list with footer "Hidden computers stay signed in to your account and are only hidden on this iPhone."
- **Add Computer** flow supports Direct Addresses (`mobile.connections.direct.*`): manually add IP[:port] hints that feed the encrypted Iroh dial ("the connection is always identity-checked. Ports are optional.").
- **Forget This Computer** (`mobile.connections.forget.*`) is a two-step confirm ("Forget Computer" / "Forget this computer?") that revokes account-level pairing; failure keeps it signed in with a retry.
- Per-computer detail (`MacComputerDetailView`, `mobile.computers.field.*`): Name, Icon, Color, custom emoji, Device ID, Build (`dev`/`nightly`/`rc`/`stable`/`staging`, with `DEV · <tag>` for tagged dev builds), Last seen, Paired since, Reports, Role ("Active (foreground)"), Source, Route updated, Workspaces count.
- **Ping** (`mobile.computers.ping.*`) opens a direct connection per known route to test reachability right now, independent of whether a workspace shows Disconnected — outcomes: `Reachable · %d ms`, "Reachable, but cmux isn't listening", "Timed out", "No route to host", "DNS lookup failed", "Blocked by Local Network privacy", "Not pingable".
- **Presence** section reads the Mac's own heartbeat to a presence service (explicitly called out as DEV-only / not-yet-universal, with separate official-build wording); explains the "online per server but This phone is not connected" case as a routing problem, not an offline Mac.
- **Keep Awake** toggle per Mac ("Keeping Mac awake" / **Keep Awake** / **Let Sleep**), mirrors the macOS Settings toggle, requires connection and a minimum cmux version.
- **Device Tree** (`DeviceTreeView.swift`) is an alternate, team-registry-driven view: devices grouped by build, expand/collapse ("Expand/Collapse builds"), tap a build to connect then a workspace to open — "Devices and their cmux builds come from your team's registry."

### Networking settings (`mobile.iroh.*`, `MobileIrohSettingsView.swift`)

A full "Networking" settings page:
- **Relay Preference**: Automatic / Custom Relays / Selected cmux Relays.
- **Custom Relays**: add/edit/remove, each with Name, Provider, Region, URL, and optional per-relay auth (None or Device Secret, stored only in this device's Keychain, "A missing secret never enables another relay provider.").
- **Private Networks**: add LAN/VPN/WireGuard/Tailscale-alternative routes by Host/Port/Name; explicitly rejects raw unauthenticated TCP ("Custom raw TCP routes are not accepted because they cannot prove the remote Mac.").
- **Never Use Relays** toggle — forces a direct/local/private path only, applies on next reconnect.
- **Relay Only** toggle — opposite constraint, keeps this device off direct/local paths.
- **Connection status readout**: Iroh Active / Direct-Only / Direct Peer-to-Peer / Inactive / Private Network / Relayed / Starting.
- **Test Connection** → Reachable / Unreachable / Test Unavailable.
- **Diagnostics** subpage: recorded event count, last failure (from a ~25-value failure-kind enum: Account Mismatch, Admission Denied, Admission Lease Expired, Authorization Failed, Cancelled, Connection Closed/Refused, Credentials Unavailable, DNS Failed, Endpoint Unavailable/Identity Mismatch, Host Unreachable, No Route, Offline, Payload Too Large, Permission Denied, Relay Policy Unavailable, Protocol Error, Resource Limit Reached, Secure Channel Failed, Send Queue Overflow, Superseded, Timed Out, Transport Idle Timeout, Unknown, Unsupported Route), last success time, **Clear Logs** (double-confirm, "This permanently removes the connection timeline stored on this device."), **Share Safe Report** (explicitly excludes terminal content, identities, addresses, relay URLs, credentials, raw errors) and a separate opt-in **Verbose Connection Log** with its own **Share Verbose Log**.
- **Debug Verification** (dev-only section): force Transport Mode Automatic / No Relay (Direct Only) / Relay Only, restarts Iroh without signing out.
- **Reset to Defaults**: relay/path prefs → Automatic; custom relays and private addresses survive but private addresses are disabled.

### Notifications & push (`mobile.notifications.*`, `mobile.push.*`, `NotificationFeed*.swift`)

Two linked surfaces: an in-app **Notification Feed** tab (always populated regardless of push settings) and OS **push alerts** (opt-in, for when the app isn't open).

**Feed** (`NotificationFeedView.swift`): chronological list grouped by day ("Today"/"Yesterday"), with a **Filter** (All Notifications / Unread), search (placeholder "Search notifications", empty state "Try another title, message, workspace, pane, or computer."), **Mark All Read** (confirms), per-row Mark as Read/Unread, and collapsible "Show/Hide earlier notifications" history groups with a count ("%lld updates"). Row shows source Mac, workspace fallback text, and a computer-status suffix format like "%@ · Reconnecting" / "%@ · Unavailable" when the originating Mac isn't live. Offline state still shows the last-synced feed ("Showing the latest alerts synced from your Macs.") with a banner to reconnect. A per-Mac "Update cmux on your Mac" nudge appears when an older Mac can't sync notification history yet.
- Empty state: "You're all caught up" / "New agent alerts will appear here as they arrive." (post-first-notification) vs. "No notifications yet" / "Every agent alert from your paired Macs will collect here, even if push alerts are off…" (true first-run).

**Push settings**: **Notify Me When Agents Need Me** master toggle; **Forwarding Mode** Always vs. **Only When Away** ("sends after the Mac is locked, asleep, or inactive"); **Hide Notification Content**; **Forward Alerts from This Mac** (per-Mac, macOS-side mirrored setting — a mutation failure rolls back to "last confirmed settings"). A **Delivery Status** line reports one of ~25 states, e.g.: Ready, Always / Ready, Only When Away / Paused, Mac Is Active / Blocked, iOS Permission Denied / Blocked, %d-Device Limit Reached / Limited, Delivered Quietly / Limited, Check iOS Presentation Settings / Blocked, Registering This Device / Blocked, Mac and iPhone Servers Differ, etc. — each paired with a matching repair action (Connect a Mac, Enable on This iPhone, Open iOS Notification Settings, Retry Notification Setup, Retry Registration, Sign In with the Matching Account, Use Always Mode).
- **Send Test Alert** exercises the whole pipeline end to end; failure reasons are distinguished (not signed in, forwarding off, Only When Away + Mac active, queue full, encoding failed, unavailable).
- Deep-link handling: tapping a push whose Mac connection is down shows "Waiting for your Mac" / "This notification will open when your Mac reconnects." with Retry/Dismiss; a push targeting a tab that's since closed shows "Tab unavailable" / "This tab is no longer available on your Mac."

**Push key exchange (`docs/phone-push-e2e.md`)**: keys are pinned over the authenticated device connection (account+build+install+device scoped); a server-directory public key alone never establishes trust. New clients accept encrypted envelopes only — there is no plaintext fallback. Key exchange runs at most 3 attempts, 3s RPC deadline each, bounded backoff, cancelled on disconnect/account change. Mac-side forwarding reports `encryption_unavailable` when no trusted recipient exists, rate-limited to one Sentry warning per minute. Diagnostics never contain notification/reply content, keys, ciphertext, credentials, or identifiers.

### Mobile state sync v2 (`docs/mobile-state-sync-v2.md`)

Replaces the old invalidate-and-refetch model. The Mac maintains two versioned collections (`workspaces`, `groups`) keyed by `epoch` (minted per Mac process launch) and per-collection monotonic `rev`; removals are tombstoned in a bounded 1024-entry ring. Phones call `mobile.sync.fetch` with their last-known `epoch`/`rev` and get either a `delta` (`from_rev`→`rev`, changed records + removed ids) or a full `snapshot` when their cursor is stale/unknown/out of tombstone range; live updates additionally arrive on the `mobile.sync.delta` event topic. Apply rule: a delta applies iff `epoch` matches and `from_rev <= local rev < to_rev`; a gap triggers a repair re-fetch — "Ordering violations therefore self-heal instead of accumulating." Old phones that never call `mobile.sync.fetch` keep getting the legacy `workspace.updated` (empty-payload, 80 ms-throttled, full refetch) behavior unchanged — the capability check is simply whether the method exists on that Mac.

## Dock (`docs/dock.md`, `dock.*` strings)

Dock is a full second panel/split container docked on the right of a cmux window, built on the **same surface and split system** as the main content area — terminals *and* browsers, same tiling. It exists so persistent side tools (git TUIs, log tails, test watchers, dashboards) live beside the main work instead of in it.

- **Per-window, not per-workspace**: every window has its own independent Dock; multiple windows can show Docks side by side; closing a window closes its Dock's terminals/browsers with it.
- **No config required**: the Dock tab bar carries the same **New Terminal** / **New Browser** / **Split Right** / **Split Down** affordances as the main area, reachable from the toolbar `+` menu or an empty Dock pane. Tabs reorder, move between Dock panes, and close like main-area tabs.
- Each Dock terminal command starts in a non-interactive login shell (keeps PATH/toolchain setup without running prompt code before a TUI); when the command exits, Dock drops into an interactive login shell in the same slot so you can inspect/rerun/exit.
- **Persistence**: after a Dock has been saved once, cmux restores that exact snapshot on relaunch/update instead of re-seeding from config — split/tab layout, divider positions, tab order/selection, terminal session metadata + agent resume state, and full browser state (navigation, zoom, profile, devtools, mute). An intentionally empty saved Dock stays empty.
- **Focused-Dock shortcuts**: when a Dock pane has keyboard focus, the standard creation/split shortcuts (Cmd+Shift+L New Browser, Cmd+T New Surface, Cmd+D / Cmd+Shift+D Split Right/Down) act on the Dock instead of the main area.
- **CLI/socket**: `cmux new-pane --placement dock`, `cmux new-surface --placement dock`; `--placement` is `workspace` (default) or `dock`. Dock-created handles come back as `dock_surface_id`/`dock_pane_id` (the ordinary `surface_id`/`pane_id` stay `null` for backward compatibility). `cmux tree`/`list-panes`/`list-pane-surfaces` mark Dock rows `[dock:workspace]` or `[dock:global]` in text, and carry `dock_scope` (`workspace`/`global`) in JSON. Ordinary surface-addressed verbs (`send`, `send-key`, `read-screen`, `capture-pane`, `focus`, `close`) accept a bare Dock surface ID directly — no special addressing syntax.
- **Configuration** — `dock.json` (fields: `id`, `title`, `type` terminal|browser, `command`/`url`, `chrome` bool defaulting true, `cwd`, `height`, `env`). Precedence: `.cmux/dock.json` (nearest project ancestor first) then `~/.config/cmux/dock.json`; relative `cwd` resolves from the config's own base directory (project dir containing `.cmux`, or home for global). `dock.json` only **seeds** — it never overlays a restored session; config seeding only runs for a Dock with no saved snapshot (new workspace/window, or a legacy pre-persistence session). Explicitly reloading the Dock config (`dock.action.reload`) replaces the current Dock with config contents regardless.
- **chrome: false** on a browser control makes it chromeless (no address bar/toolbar); Focus Address Bar is then intentionally a no-op — navigation still works via the page itself or `cmux browser <surface> goto/reload`.
- **Trust gate**: the first time cmux sees a project's `.cmux/dock.json` it shows a trust dialog ("This project wants to start commands from its Dock config." / **Trust and Start**) before launching any control; changing the config changes its trust fingerprint and re-prompts. The global `~/.config/cmux/dock.json` is personal config and starts without a prompt.
- Empty Dock with no config offers a starter-config prompt plus **Copy Agent Prompt** / **Show Agent Prompt** (a canned prompt for an AI agent to write `.cmux/dock.json`) and **Docs**.
- Errors surface as a named dialog ("Dock Config Error"): blank control command/id/URL, duplicate control ids, unknown control type, unsupported surface type for Dock placement, conflicting routing selectors, config load/open failure.
- `dock.inactiveHost.title` "Global Dock is active in another window" — the global Dock can only be hosted by one window at a time.
- Suggested/alternate names documented for the feature itself: TUI Dock, Command Dock, Control Dock, Deck, Sidecar (Dock is the shipped name).

## Canvas (`docs/canvas-layout-design.md`, `Packages/macOS/CmuxCanvas`, `Sources/Canvas/*`)

An opt-in freeform 2D layout mode for a workspace's panes, alternative to the default `bonsplit` tree layout. Every panel type (terminal, browser, markdown, file preview, agent session, …) becomes an individually resizable, freely-positioned pane on an infinite scrollable canvas ("Command+scroll pans the canvas from anywhere" — `canvas.commandScrollHint`). A workspace switches modes without losing panels; switching back restores the previous split tree.

- **Two-layer architecture**: `CmuxCanvas` is a pure, Foundation-only (no AppKit/CoreGraphics), fully unit-tested model — pane frames, gap math, snapping, alignment/distribution, spatial focus, new-pane placement, viewport math — declared for both macOS and iOS so a touch canvas could reuse it later. `Sources/Canvas/` is the thin AppKit rendering/input layer (`NSScrollView` + flipped document view; panes are real AppKit subviews).
- **Terminal hosting is direct, not portal-anchored**: in split mode terminals are hosted by a window-level portal registry and resized to their visible rect as ancestors clip them; on a scrolling canvas that would thrash Ghostty surfaces continuously, so canvas mode detaches the terminal's `GhosttySurfaceScrollView` from that portal and parents it directly into the canvas pane view — full size always, native scroll clipping/momentum/rubber-banding. Non-terminal panes still route through the portal system in v1 (`NSHostingView` per pane), which is a known, documented imperfection: portal-hosted content clips by resizing at the viewport edge and always renders above direct-hosted content — terminals are "the flawless path", others "correct-but-not-perfect until they get direct hosting too."
- **Mode switching**: splits→canvas seeds each pane's canvas frame from the bonsplit layout snapshot, then normalizes to the canonical gap. canvas→splits keeps the previous bonsplit tree alive underneath the whole time (panels are never removed from its bookkeeping) and just re-mounts it; panels created while in canvas mode get appended as tabs to the focused bonsplit pane on the way back, so nothing is lost either direction.
- **Offscreen pane lifecycle** (`CanvasPaneLifecycle`), reclassified on every scroll/resize/zoom: `visible` (intersects viewport + one margin, live), `nearby` (within prefetch margin, live/cheap), `offscreen` (terminals get the same occlusion hint as hidden split panes; browsers keep their existing hidden-webview discard policy). Frames never change while offscreen, so there's no reflow on re-entry.
- **Model primitives**: `CanvasRect/Point/Size` (Double, Codable, Hashable); `CanvasLayout` (ordered back→front pane list, frames, focused id, add/remove/move/resize/bring-to-front, Codable for persistence); `CanvasMetrics` (canonical gap, snap threshold, min pane size — user-configurable); `CanvasSnapEngine` (neighbor edge, neighbor edge+gap, center-alignment snap candidates plus guide lines while dragging/resizing); `CanvasAlignment` (align lefts/rights/tops/bottoms, equalize widths/heights, distribute horizontally/vertically at the canonical gap, and a one-shot **tidy** — row-band packing that preserves sizes and spatial order); `CanvasSpatialNavigator` (nearest pane left/right/up/down by directional half-plane + orthogonal misalignment penalty, deterministic tie-break); `CanvasPlacement` (new-pane frame near the focused pane: right, below, left, above, then outward scan — never disturbing existing panes); `CanvasViewportMath` (minimal scroll to reveal a rect with margin; fit-all magnification).
- **Actions**, all routed through one shared `CanvasActionExecutor` (keyboard shortcuts, command palette, View menu, and `canvas.*` debug-socket verbs all call the same entry point): toggle canvas layout, focus left/right/up/down, focus previous, reveal focused pane, overview (fit all), zoom to 100%, align lefts/rights/tops/bottoms, equalize widths/heights, distribute horizontally/vertically, tidy canvas. Spatial focus reuses the existing split-focus keyboard shortcuts when a workspace is in canvas mode (same shortcut, mode-appropriate behavior).
- Settings: `canvas.paneGap` (points), `canvas.snapping` (bool); all shortcuts editable in Settings and `~/.config/cmux/cmux.json`.
- **Minimap** (`canvas.minimap.*`): click-or-drag overview to move the canvas viewport, with an accessibility label/help string.
- **Close pane** control on each canvas pane (`canvas.pane.close.help` "Close Pane").
- Persistence: `SessionWorkspaceSnapshot` gains `layoutMode` and an optional encoded `CanvasLayout`; restore rebuilds the canvas exactly, panes keep their frames across restarts.

## Diff viewer (`diffViewer.*` strings, `CLI/CMUXCLI+{TypedDiffViewer,DiffViewerShortcuts,DiffSidecar,DiffViewerBundledAssets}.swift`, `Native/DiffSidecar`)

The diff viewer is a webview-hosted React app fed by a Rust sidecar process (`cmux-diff-sidecar`), not a native Swift view. The sidecar is a single-shot command boundary: the app sends one typed request over stdin/stdout, the sidecar computes and exits — there is no TCP listener or idle backend process. Diff HTML/modules/patch files are served through an app-owned `cmux-diff-viewer://` URL allowlist. The stdio transport accepts at most one 1 MiB request and requires EOF within 10 seconds; a timed-out, oversized, or malformed envelope returns a typed failure under a fixed sentinel ID (`__cmux_untrusted_request__`) rather than trusting any caller-supplied ID before the envelope fully parses. `src/protocol.rs` is the source of truth for the typed protocol; generated TypeScript types are checked in CI for staleness. React can select a `fetch`, `webSocket`, or `webKit` transport depending on host (macOS uses WebKit reply messages over sidecar stdio today; future browser hosts could use Fetch/WebSocket without changing the command/result shapes).

Build/verification hardening: Rust is a required macOS build dependency, pinned via `rust-toolchain.toml` (Rust 1.88.0, both Apple targets), always invoked through rustup with `--locked`. Release builds use size optimization, fat LTO, 1 codegen unit, stripped symbols, per-arch isolated target dirs, `MACOSX_DEPLOYMENT_TARGET=14.0`. `verify-diff-sidecar-artifact.sh` rejects missing arch slices, non-system dynamic dependencies, a wrong deployment target, linkable symbols, wrong executable permissions, or a binary over 5 MiB; release signing re-runs the same check and requires a valid signature. A dedicated benchmark script measures manifest decoding, patch reads, and the real parser/batcher against 2,000 files with CI-enforced p95/throughput budgets.

User-facing surface (from `diffViewer.*` strings):
- **Diff sources/targets**: Staged changes, Unstaged changes, Branch diff (with a branch picker — filterable list grouped into Suggested/Recent/Branches/Remotes/Worktrees, "Comparing {head} against {base}", raw-ref entry via **Use "{ref}" (raw)**, live generation state "Generating diff against {ref}..."), Last turn diff (the agent's most recent turn). Each has its own "no changes" empty state text.
- **View controls**: Classic vs. a newer rendering path; unified vs. split diff toggle; word diffs on/off; word wrap on/off; line numbers on/off; backgrounds on/off; collapse/expand all diffs; collapse/expand unchanged context; a file-search filter (**Find in diff**, next/previous match, close) and a separate file-tree/file-list search (**Show/Hide file search**, **Show/Hide files**).
- **Vim-style keyboard shortcuts** (`CMUXCLI+DiffViewerShortcuts.swift`, all user-editable): `j`/`k` scroll down/up, Ctrl-d/Ctrl-u half-page down/up, Ctrl-n/Ctrl-p (Emacs-style) line down/up, Shift-G scroll to bottom, `g g` (chord) scroll to top, `/` open file search, `] f` next file, `[ f` previous file.
- **Per-line/word rendering**: mode-change annotations ("Mode {old} → {new}"), binary-file placeholder, additions/deletions/diff-stats counts, a **Copy git apply command** action (toast "Copied git apply command", failure "Could not copy git apply command.").
- **Comments** (see below) are inline in this same viewer: **Add comment**, placeholder "Leave a comment", Save as **Comment**, Cancel, Edit, Delete, and an **Outdated** badge for a comment whose anchor no longer matches current content.
- Loading/error states are staged and explicit: "Parsing diff...", "Rendering diff...", "Loading renderer...", "Loading diff: %@", and a hard failure "Could not render this diff. Check the patch input and try again." / "No file diffs found in patch input." / an allowlist-too-large guard error.

## Review comments (`diffComments.*`, `cmux comments`, `cmux review`)

Two related but distinct systems, both content-addressed in the repo's own Git metadata (no cmux app or socket required to read them for `review`):

- **`cmux comments list [--repo <path>] [--all] [--json]`** — lists review comments the user left in the diff viewer, stored per git repository. Default lists only **pending** comments; `--all` includes ones already delivered to an agent through a TextBox submission (i.e., consumed). Text output: a header "1 review comment (repo: %@)" / "%1$lld review comments (repo: %2$@)" then one line per comment `- <path>:<startLine>[-<endLine>] [pending|consumed]`, with an indented `anchor: <lineText>` and the comment message. `--repo` requires a real path (a leading-dash path must be passed as `./-name`); any other unexpected argument is rejected outright ("Supported: --repo <path>, --all, --json"). The repo root is resolved via `git rev-parse --show-toplevel` before hitting the socket (`comments.list`, with `include_consumed` when `--all`).
- **`diffComments.bridge.notAllowed`** — "This page cannot use diff comments." (a webview-bridge guard for pages that aren't a real diff viewer session.)
- **`cmux review list|show|findings [--repo <path>] [--json]`** — reads local *adversarial-review receipts* (distinct from user comments): content-addressed JSON files under the repo's `cmux/reviews` git-path, each a schema-validated payload (`schema_version` must be 1, `policy_version`, `repository_root`, optional 64-hex `ruleset_sha256`, `source`, `brief`, `summary`, `findings[]`, ISO-8601 `created_at`; unexpected/missing top-level fields make the whole receipt invalid). `list` shows runs newest-first; `show` shows one (default `latest`); `findings` shows one run's findings, hiding refuted/suppressed ones unless `--all` is passed. These are written by "the review skill" (an agent-side tool), and this CLI command is a pure reader — it works even with cmux not running.

## SwiftUI interpreter surface / Custom Sidebars (`docs/swiftui-interpreter-surface.md`, `docs/custom-sidebars.md`, `customSidebarRenderer.*`)

**Custom Sidebars** ("vibe-code your own cmux sidebar") let a user (or an agent on their behalf) author a small SwiftUI-style `.swift` file that is *interpreted at runtime* — no Xcode, no build/sign step — and renders as a real native sidebar panel, hot-reloading on save, bound to live cmux state (workspaces, tabs, etc.), and able to trigger `cmux(...)` commands on tap (e.g. selecting a workspace, focusing a tab). It's beta and on by default; toggled off in Settings → Custom Sidebars (`customSidebars.beta.enabled`) — while off, custom sidebars simply don't appear. Two renderer modes are offered explicitly to the user:
- **In-app (full input)** — "Renders as native SwiftUI inside cmux with hover, focus, and typing. A faulty sidebar shares the app process."
- **Isolated process** — "Renders in a crash-isolated helper process. Clicks only: no hover, focus, or typing."

Iterating: `cmux sidebar open <name>` opens a sidebar as a pane and hot-reloads it live while editing.

This is distinct from compiled ExtensionKit sidebars (ordinary Swift, sandboxed, in `Examples/SampleSidebarExtensionApp` and `Packages/macOS/CmuxExtensionKit`), which the doc explicitly points elsewhere for.

The interpreter itself (`docs/swiftui-interpreter-surface.md`) is a swift-syntax tree-walker with **no compiler, no toolchain, no type checker** — it lowers a `.swift` file into a `RenderNode` IR bridged to real SwiftUI, with an erased/tagged runtime type system. Documented current gap and roadmap (not yet built, for context on what an authored sidebar can/can't do today): no mutable `@State`/binding engine yet (each render rebuilds a fresh read-only environment), no user struct/enum/custom-View interpretation, a flat string-only modifier/style system (no real Color/gradient/Material handling), and modifiers can't take an arbitrary child subtree (a trailing closure on `.background`/`.overlay` is silently dropped today). A capability matrix in the doc tracks ●/◐/○ support per SwiftUI symbol.
